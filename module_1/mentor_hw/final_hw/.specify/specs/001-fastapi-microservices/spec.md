## User Scenarios & Testing *(mandatory)*

> TEST-REQUIREMENT: Для каждой истории уровня P1 тесты обязаны быть предоставлены в спецификации и должны
> быть написаны ДО реализации (TDD). Изменения публичных интерфейсов/контрактов требуют контрактных/интеграционных тестов.

### User Story 1 - Управление задачами (TODO Service) (Priority: P1)

Пользователь хочет иметь возможность создавать, просматривать, обновлять и удалять задачи через API, чтобы управлять своим списком дел. Также требуется простой веб-интерфейс для взаимодействия.

**Why this priority**: Базовая функциональность первого микросервиса.

**Independent Test**: Запустить сервис TODO, выполнить полный цикл CRUD операций через API и убедиться, что данные сохраняются в БД.

**Acceptance Scenarios**:

1. **Given** Сервис запущен и БД пуста, **When** Пользователь отправляет POST /items с данными задачи, **Then** Задача создается, возвращается ID, и она появляется в списке GET /items.
2. **Given** Существует задача с ID 1, **When** Пользователь отправляет PUT /items/1 с новыми данными, **Then** Задача обновляется.
3. **Given** Существует задача с ID 1, **When** Пользователь отправляет DELETE /items/1, **Then** Задача удаляется и больше не возвращается в GET /items.
4. **Given** Сервис перезапущен, **When** Пользователь запрашивает список задач, **Then** Ранее созданные задачи доступны (персистентность).

---

### User Story 2 - Сокращение ссылок (ShortURL Service) (Priority: P1)

Пользователь хочет сокращать длинные URL и использовать короткие ссылки для перенаправления, а также просматривать статистику по ссылке.

**Why this priority**: Базовая функциональность второго микросервиса.

**Independent Test**: Запустить сервис ShortURL, сократить ссылку, перейти по короткой ссылке и убедиться в редиректе.

**Acceptance Scenarios**:

1. **Given** Сервис запущен, **When** Пользователь отправляет POST /shorten с длинным URL, **Then** Возвращается короткий ID/ссылка.
2. **Given** Короткая ссылка создана, **When** Пользователь переходит по GET /{short_id}, **Then** Происходит редирект на исходный URL.
3. **Given** Короткая ссылка создана, **When** Пользователь запрашивает GET /stats/{short_id}, **Then** Возвращается JSON с информацией о полном URL.
4. **Given** Сервис перезапущен, **When** Пользователь использует старую короткую ссылку, **Then** Редирект работает корректно.

---

### User Story 3 - Контейнеризация и развертывание (Priority: P1)

Разработчик хочет запускать оба сервиса в Docker-контейнерах с сохранением данных на хосте, чтобы обеспечить переносимость и сохранность данных.

**Why this priority**: Требование к инфраструктуре и сдаче проекта.

**Independent Test**: Собрать Docker-образы, запустить контейнеры с volume, создать данные, перезапустить контейнеры и проверить наличие данных.

**Acceptance Scenarios**:

1. **Given** Dockerfile для TODO сервиса, **When** Выполняется `docker build` и `docker run` с volume, **Then** Сервис доступен на порту 80 и данные сохраняются в volume.
2. **Given** Dockerfile для ShortURL сервиса, **When** Выполняется `docker build` и `docker run` с volume, **Then** Сервис доступен на порту 80 и данные сохраняются в volume.
3. **Given** Оба сервиса запущены, **When** Проверяется версия Python внутри контейнера, **Then** Она соответствует 3.14 (или совместимой версии, если 3.14 недоступна).

### Edge Cases

- Что если запрошен несуществующий ID задачи или short_id? -> Возвращать 404 Not Found.
- Что если отправлен некорректный JSON? -> Возвращать 422 Unprocessable Entity (стандарт FastAPI).
- Что если URL для сокращения некорректен? -> Возвращать ошибку валидации.
- Конфликт портов при запуске обоих сервисов на одном хосте (оба хотят 80)? -> Инструкция должна предусматривать маппинг портов (например, 8001:80 и 8002:80) или запуск по очереди. В требованиях сказано "откройте порт 80" и "запустить uvicorn на хосте 0.0.0.0, порт 80" внутри контейнера. При запуске `docker run` пользователь сам выберет внешний порт.

## Requirements *(mandatory)*

### Functional Requirements

**TODO Service:**
- **FR-001**: Сервис должен предоставлять REST API для CRUD операций над задачами (POST, GET, PUT, DELETE).
- **FR-002**: Модель задачи должна содержать: id (int/str), title (str), description (str), completed (bool, default=false).
- **FR-003**: Данные должны сохраняться в SQLite базе данных по пути `/app/data/todo.db`.
- **FR-004**: Таблица задач должна создаваться автоматически при старте сервиса, если не существует.
- **FR-005**: Сервис должен иметь простой HTML frontend (доступный по `/` или `/ui`) для работы с API.

**ShortURL Service:**
- **FR-006**: Сервис должен принимать JSON `{"url": "..."}` на POST /shorten и возвращать `short_id` или полную короткую ссылку.
- **FR-007**: GET /{short_id} должен перенаправлять (301/302/307) на полный URL.
- **FR-008**: GET /stats/{short_id} должен возвращать JSON с информацией о полном URL.
- **FR-009**: Данные должны сохраняться в SQLite базе данных по пути `/app/data/shorturl.db`.
- **FR-010**: Таблица ссылок должна создаваться автоматически при старте сервиса.
- **FR-011**: Сервис должен иметь простой HTML frontend для ввода ссылок.

**General & Docker:**
- **FR-012**: Оба сервиса должны быть написаны на Python (версия 3.14, если доступна, иначе 3.13/latest stable).
- **FR-013**: Использовать фреймворк FastAPI и сервер Uvicorn.
- **FR-014**: Для каждого сервиса должен быть Dockerfile на базе `python:3.14-slim` (или аналог).
- **FR-015**: Контейнеры должны экспонировать порт 80.
- **FR-016**: Данные должны храниться в volume, смонтированном в `/app/data`.
- **FR-017**: Проект должен содержать `README.md` с инструкциями по запуску через `docker run`.
- **FR-018**: Использовать `uv` в качестве менеджера пакетов вместо `pip` и `requirements.txt`.

### Key Entities

- **Task**: Задача в TODO листе. Атрибуты: id, title, description, completed.
- **ShortURL**: Запись о сокращенной ссылке. Атрибуты: short_id (уникальный ключ), full_url (исходная ссылка).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Оба сервиса успешно собираются в Docker-образы без ошибок.
- **SC-002**: Контейнеры запускаются и работают стабильно, обслуживая HTTP запросы.
- **SC-003**: Данные (задачи и ссылки) сохраняются между перезапусками контейнеров (при использовании volume).
- **SC-004**: API обоих сервисов соответствует спецификации (все эндпоинты работают).
- **SC-005**: Пользователь может взаимодействовать с сервисами через браузер (простой frontend).
